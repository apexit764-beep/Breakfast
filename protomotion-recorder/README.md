# Figma Prototype Recorder

سكربت بيفتح رابط بروتوتايب Figma في متصفح، بيشغّله، وبيسجّله فيديو.

## التنصيب (مرة وحدة)

محتاج [Node.js](https://nodejs.org) مثبّت على الجهاز.

افتح PowerShell جوّا مجلد `protomotion-recorder` وشغّل:

```
npm install
npx playwright install chromium
```

(`npm install` بينزّل كمان نسخة ffmpeg جاهزة، فما إلك حاجة تنصّب إشي غيرها.)

## الاستخدام

```
node record.js -u "رابط_البروتوتايب"
```

الفيديو بينحفظ باسم `prototype.mp4` (H.264، 60 إطار/ثانية) في نفس المجلد. لو بدك webm حط `-o prototype.webm`.

**التسجيل بيوقف لما تضغط Enter.** ما في توقف تلقائي — السكربت ما بياخد أي screenshots أثناء التصوير عشان ما يشوّش على الفيديو. في بس حد أقصى للأمان (`-m`، افتراضياً 10 دقايق) عشان ما يضل يسجّل لو نسيته شغّال.

## الخيارات

| الخيار | الوصف | الافتراضي |
|---|---|---|
| `-u, --url` | رابط بروتوتايب Figma (مطلوب) | — |
| `-o, --output` | مسار ملف الإخراج — `.mp4` أو `.webm` | `prototype.mp4` |
| `--fps` | إطارات بالثانية | `60` |
| `-q, --quality` | جودة الترميز (CRF) — أقل = أنقى وأكبر حجماً | `18` |
| `-m, --maxdur` | حد أقصى لمدة التسجيل بالثواني (أمان) | `600` |
| `-p, --pause` | ثواني بين كل ضغطة تلقائية | `2` |
| `-w, --width` | عرض التصوير | `1536` |
| `-h, --height` | ارتفاع التصوير (بينتجاهل إذا استعملت `-a`) | `864` |
| `-a, --aspect` | نسبة الأبعاد للفيديو: `16:9`، `4:5`، `1.91:1`، أو رقم مثل `1.78` — الارتفاع بينحسب من `-w` | — |
| `-r, --res` | مقاس ثابت بدل النسبة، مثل `2880x1838` | — |
| `-d, --design-width` | عرض الفريم في Figma (مثلاً `1920`) — **ضرورية لما مقاس الفيديو أكبر من التصميم**، بدونها بيطلع رمادي حوالين التصميم | — |
| `-s, --scale` | كثافة رسم إضافية (حواف أنعم) — ما بتغيّر دقة الملف | `1` |
| `--fit` | كيف بينحط فريم Figma جوّا المقاس: `width` / `screen` / `actual` | `width` |
| `--upscale` | مع `-d`: صوّر على مقاس التصميم وكبّر الفيديو عند الترميز (إطارات أعلى، وضوح أقل شوي) | مطفي |
| `--manual` | إنت بتضغط بنفسك، السكربت بيسجّل بس | مطفي |
| `--headless` | تشغيل بدون متصفح ظاهر | مطفي |
| `--debug` | يطبع تغيّرات حجم/zoom الـ canvas | مطفي |

اضغط **Enter** بأي لحظة عشان توقف التسجيل وتحفظه.

## أمثلة

```
node record.js -u "https://figma.com/proto/..."
node record.js -u "https://figma.com/proto/..." --manual
node record.js -u "https://figma.com/proto/..." --debug
node record.js -u "https://figma.com/proto/..." -p 3 -w 1440 -h 900
node record.js -u "https://figma.com/proto/..." -a 16:9 -w 2880 -d 1920
node record.js -u "https://figma.com/proto/..." -a 4:5 -w 1080 -d 1080
node record.js -u "https://figma.com/proto/..." -r 2880x1838 -d 1920
```

## الصيغة والإطارات (mp4 و 60fps)

الملف بيطلع **mp4 / H.264 بـ 60 إطار/ثانية** افتراضياً. المسجّل مش مسجّل Playwright الجاهز (هداك مقيّد بـ 25 إطار و1 ميجابت/ث) — إحنا بناخد الإطارات من Chromium مباشرة عبر CDP وبنمرّرها لـ ffmpeg، فإحنا اللي نتحكم بالإطارات والجودة.

```
node record.js -u "..." --fps 60 -q 18        # الافتراضي
node record.js -u "..." --fps 30              # ملف أخف
node record.js -u "..." -q 14                 # جودة أعلى وحجم أكبر
node record.js -u "..." -o clip.webm          # webm (VP9) بدل mp4
```

### ⚠️ الإطارات مقابل المقاس

الـ 60 إطار مضمونة **في الملف**، بس عدد الإطارات اللي المتصفح فعلياً يرسمها بيقلّ لما المقاس يكبر. أرقام مقاسة على جهاز بدون كرت رسوميات (أسوأ حالة):

| المقاس | إطارات مرسومة فعلياً |
|---|---|
| 1280×720 | ~59/ث |
| 1536×864 | ~50/ث |
| 1920×1226 | ~28/ث |
| 2880×1838 (مع `-d 1920`) | ~5–9/ث |

السبب: `-d 1920` مع فيديو 2880 معناها الصفحة بترندر على 4320×2757 بكسل فعلي — شغل ثقيل. على جهاز فيه كرت رسوميات الأرقام بتطلع أعلى بكتير، وبعد كل تسجيل السكربت بيطبعلك الرقم الحقيقي:

```
Frames:    60 fps in the file; Chromium painted 52.4 new frames/s during the recording
```

**عشان انتقالات ناعمة فعلاً**: صوّر على مقاس التصميم نفسه (بدون تكبير كثافة):

```
node record.js -u "..." -a 1920:1226 -w 1920 -d 1920
```

ولو ضروري 2880: جرّبه وشوف الرقم المطبوع؛ إذا كان أقل من ~45، إما صغّر المقاس أو خلّي `--fps 30` (بتطلع أنعم من 60 إطار نصهم مكرر).

## لما المطلوب مقاس أكبر من تصميمك (نفس النسبة)

مثال: الموشن جرافيك طالب **2880×1838**، وتصميمك في Figma **1920×1226** (نفس النسبة). ٣ حلول، مرتّبة من الأفضل:

**1) كبّر الفريم في Figma لـ 2880×1838** — الأنضف. في Figma: اختار الفريم، استعمل أداة الـ Scale (زر `K`) وحدّد 150%، أو حدّد `W = 2880` مع تثبيت النسبة. بعدها صوّر بدون `-d` أبداً:

```
node record.js -u "..." -r 2880x1838
```

Figma بيعيد رسم كل شي (نصوص، فيكتور، ظلال) على المقاس الحقيقي — أوضح نتيجة وأعلى fps ممكن لهالمقاس. الشي الوحيد اللي ممكن يخفّ وضوحه هو الصور الفوتوغرافية إذا دقتها الأصلية أقل من 1.5x.

**2) `-d 1920` (الوضع الحاد)** — إذا ما بتقدر تعدّل ملف Figma:

```
node record.js -u "..." -r 2880x1838 -d 1920
```

الوضوح ممتاز، بس الرسم ثقيل (4320×2757 بكسل فعلي) فالإطارات بتقل — على جهاز بدون كرت رسوميات نزلت لـ ~8 إطار/ثانية.

**3) `-d 1920 --upscale` (الوضع الناعم)** — نفس المقاس المطلوب بإطارات عالية:

```
node record.js -u "..." -r 2880x1838 -d 1920 --upscale
```

بيصوّر على 1920×1226 (مقاس تصميمك، خفيف وسريع) وبعدين ffmpeg يكبّره لـ 2880×1838 بـ lanczos. على نفس الجهاز أعطى **~30 إطار/ثانية مقابل ~8** للوضع الحاد، والفرق في الوضوح بسيط جداً.

**بديل رابع**: سلّم الموشن جرافيك ملف **1920×1226 بـ 60 إطار** وخلّيه هو يكبّره في After Effects — هو أصلاً رح يعمل composite، وتكبير AE ممتاز:

```
node record.js -u "..." -a 1920:1226 -w 1920
```

## نسبة الأبعاد والمقاس (Aspect Ratio)

المقاس النهائي للفيديو إنت اللي بتحدده، **مهما كان مقاس الفريم في Figma**.

**بالنسبة (المُوصى فيه):** بتحدد النسبة بـ `-a` والعرض بـ `-w`، والارتفاع بينحسب لحاله:

```
node record.js -u "..." -a 16:9   -w 2880 -d 1920   ->  2880x1620
node record.js -u "..." -a 4:5    -w 1080 -d 1080   ->  1080x1350
node record.js -u "..." -a 1.91:1 -w 1200 -d 1200   ->  1200x628
```

**بمقاس ثابت:** إذا بدك رقم محدد بالظبط:

```
node record.js -u "..." -r 2880x1838 -d 1920        ->  2880x1838
```

المعادلة: **دقة الفيديو = العرض × الارتفاع** بالظبط، والسكربت بيطبع المقاس والنسبة قبل ما يبدأ التسجيل عشان تتأكد.

### ⚠️ `-d, --design-width` — لازم تحطها لما الفيديو أكبر من التصميم

في حدّين لازم تعرفهم:

1. **Figma بيصغّر بس، ما بيكبّر.** إذا التصميم عندك عرضه 1920 وطلبت فيديو 2880، Figma بيخلّي التصميم 1920 وبيملا الباقي بلون خلفية البروتوتايب (رمادي).
2. **مسجّل الفيديو ما بيكبّر الصورة كمان.** إذا مقاس الفيديو أكبر من نافذة المتصفح، بيحط خلفية حوالين الصورة بدل ما يمدّها.

`-d` بتحل الاثنين: بتقوله عرض الفريم في Figma، فبيرندر الصفحة بكثافة أعلى (1920 → 2880 يعني 1.5x) وبيكبّر الـ canvas بنفس النسبة — التصميم بيملا الكادر كامل وبدقة كاملة بدون رمادي وبدون بكسلة.

```
node record.js -u "..." -r 2880x1838 -d 1920
```

السكربت بيطبعلك سطر يوضّح شو صار:

```
Video:     2880x1838  aspect 1440:919 (1.567)   (from --res 2880x1838)
Window:    2880x1838 @1.5x density
Design:    1920px wide -> rendered at x1.5 density to fill the frame (sharpest)
```

لو مقاس الفيديو نفس مقاس التصميم أو أصغر، ما إلك حاجة لـ `-d`.

### `--fit` — كيف بينحط تصميم Figma جوّا هالمقاس

لما نسبة الفيديو تختلف عن نسبة الفريم في Figma:

| القيمة | شو بتعمل |
|---|---|
| `width` (افتراضي) | بتملا العرض كامل، وممكن يتقصّ من فوق/تحت |
| `screen` | بيبان الفريم كامل، والفاضي بينملا بلون خلفية البروتوتايب |
| `actual` | بدون تصغير/تكبير |

```
node record.js -u "..." -a 9:16 -w 1080 --fit screen
```

**ملاحظات:**
- `--fit` بيتحكم بإعداد Figma نفسه؛ أما `-d` فبتشتغل مهما كان `--fit` — فلو ظهر رمادي، `-d` هي الحل الأكيد.
- الأرقام الفردية بتنضبط لأقرب رقم زوجي لأن ترميز الفيديو بيفضّل الأبعاد الزوجية (مثلاً `1839` بتصير `1840`).
- المقاسات الكبيرة (فوق ~3000 بكسل) مع `-d` بترندر بكثافة عالية، فبتزيد استهلاك المعالج والذاكرة؛ لو التسجيل صار متقطّع صغّر `-w`.

## تشخيص مشكلة الـ zoom blink

إذا الفيديو فيه تكبير/تصغير لحظي أثناء الانتقال بين الشاشات:

1. الـ screenshots اللي كانت بتشتغل أثناء التصوير (السبب الأول المشتبه فيه) **انشالت من السكربت نهائياً**، فالمفروض تكون المشكلة راحت.
2. إذا ضلّت، شغّل بـ `--debug` وشوف شو بيتغيّر:
   - `buffer` أو `css` بيتغير → حجم عنصر الـ canvas بيتغير.
   - `transform` بيتغير → Figma بيغيّر الـ zoom.
   - ما في تغيّر → المشكلة جوّا WebGL، وبتنحل من إعدادات الانتقال في Figma.
3. جرّب تغيّر نوع الانتقال في Figma لـ **Instant** أو **Dissolve** بدل Move In / Slide In / Push.

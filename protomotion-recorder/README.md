# Figma Prototype Recorder

سكربت بيفتح رابط بروتوتايب Figma في متصفح، بيشغّله، وبيسجّله فيديو **mp4 بنفس مقاس الفريم تاعك بالظبط** — بدون تكبير ولا تصغير ولا زوم.

## التنصيب (مرة وحدة)

محتاج [Node.js](https://nodejs.org) مثبّت على الجهاز.

افتح PowerShell جوّا مجلد `protomotion-recorder` وشغّل:

```
npm install
npx playwright install chromium
```

(`npm install` بينزّل كمان نسخة ffmpeg جاهزة، فما إلك حاجة تنصّب إشي غيرها.)

## الاستخدام

حدّد مقاس الفريم اللي عندك في Figma:

```
node record.js -u "رابط_البروتوتايب" -w 1920 -h 1226
```

الفيديو بينحفظ `prototype.mp4` — H.264، 60 إطار/ثانية، بمقاس 1920×1226 بالظبط.

**التسجيل بيوقف لما تضغط Enter.** ما في توقف تلقائي ولا screenshots أثناء التصوير. في بس حد أقصى للأمان (`-m`، افتراضياً 10 دقايق).

## الخيارات

| الخيار | الوصف | الافتراضي |
|---|---|---|
| `-u, --url` | رابط بروتوتايب Figma (مطلوب) | — |
| `-o, --output` | مسار ملف الإخراج — `.mp4` أو `.webm` | `prototype.mp4` |
| `-w, --width` | عرض الفريم في Figma | `1920` |
| `-h, --height` | ارتفاع الفريم في Figma | `1080` |
| `--fps` | إطارات بالثانية | `60` |
| `-q, --quality` | جودة الترميز (CRF) — أقل = أنقى وأكبر حجماً | `18` |
| `--jpeg` | جودة الإطارات المسحوبة من المتصفح (1–100) — قلّلها لو المتصفح ما بيلحق | `92` |
| `--preset` | سرعة/جودة ترميز x264: `ultrafast` … `medium` — الأبطأ أنقى بس بياخد CPU من المتصفح | `ultrafast` |
| `-m, --maxdur` | حد أقصى لمدة التسجيل بالثواني (أمان) | `600` |
| `-p, --pause` | ثواني بين كل ضغطة تلقائية | `2` |
| `--manual` | إنت بتضغط بنفسك، السكربت بيسجّل بس | مطفي |
| `--headless` | تشغيل بدون متصفح ظاهر | مطفي |
| `--uncap` | يشيل قيد الـ vsync عن Chromium — ممكن يرفع الإطارات وممكن يعمل تهزيز، جرّب الاثنين | مطفي |
| `--debug` | يطبع تغيّرات حجم الـ canvas | مطفي |

## أمثلة

```
node record.js -u "https://figma.com/proto/..." -w 1920 -h 1226
node record.js -u "https://figma.com/proto/..." -w 1920 -h 1226 --manual
node record.js -u "https://figma.com/proto/..." -w 1920 -h 1226 --fps 30
node record.js -u "https://figma.com/proto/..." -w 1920 -h 1226 -o clip.webm
```

## قراءة الأرقام أثناء التسجيل

كل 5 ثواني بيطبع سطر حالة:

```
[ 15s] 58.4 fps painted  queue 0.0 MB  rss 150 MB
```

- **fps painted** = الإطارات اللي المتصفح فعلياً رسمها بهالفترة. لو قريبة من `--fps` فالحركة ناعمة.
- **queue** = حجم الإطارات المستنية عند الـ encoder. لازم تضل قريبة من صفر. لو بتكبر، الـ encoder هو المشكلة.
- **rss** = ذاكرة السكربت. لازم تضل ثابتة تقريباً.

وبالنهاية بيطبع المعدل العام، وإذا الإطارات نزلت أثناء التسجيل بيقولك مين السبب: الـ encoder ولا المتصفح.

## إذا الحركة صارت متقطّعة (glitch) بعد أول ثواني

هاي الأسباب المعروفة وشو انعمل فيها:

1. **الـ encoder بيتراكم عليه شغل.** النسخة القديمة كانت تكتب 60 إطار بالثانية للـ encoder (بتكرّر الإطار الواقف بنفسها)، فلما x264 ما يلحق بتتجمّع الإطارات في الذاكرة وياكل CPU من المتصفح — والنتيجة تدهور تدريجي بعد أول ~15 ثانية. هلأ كل إطار ينكتب **مرة وحدة** مع وقت وصوله، و ffmpeg هو اللي يبني الـ 60 إطار. القياس: قبل ~40% من الإطارات مكررة وغير منتظمة، بعد التعديل 90%+ وثابتة على مدى 45 ثانية، والـ queue ضلّت صفر والذاكرة ثابتة.
2. **إعدادات `--disable-frame-rate-limit` / `--disable-gpu-vsync`** كانت مفتوحة افتراضياً، فـ Chromium بيرسم بلا سقف وبياكل CPU لازم للترميز، وكمان بيخرب انتظام الإطارات. صارت مطفية افتراضياً — لو بدك تجربها استعمل `--uncap`.
3. **التصوير بكثافة رسم أعلى من 1:1** (كان عبر `-d`) معناه رسم ملايين بكسل زيادة. انشال كلياً — التصوير هلأ 1:1 بمقاس الفريم.
4. **البروتوتايب نفسه.** لو شاشة معيّنة فيها صور ضخمة أو أنيميشن ثقيل، Figma بيبطئ عندها. سطر الحالة بيبيّن الثانية اللي صار فيها الهبوط، فبتعرف إذا السبب شاشة معيّنة ولا الجهاز.

**لو ضلّت متقطّعة**، بالترتيب:

```
node record.js -u "..." -w 1920 -h 1226 --jpeg 75      # سحب الإطارات أخف
node record.js -u "..." -w 1920 -h 1226 --fps 30       # 30 إطار حقيقي أنعم من 60 نصهم مكرر
node record.js -u "..." -w 1920 -h 1226 --uncap        # جرّب بلا سقف vsync
```

وسكّر البرامج التقيلة (Photoshop / AE / Chrome تانية) أثناء التصوير — التصوير والترميز الاثنين على نفس الجهاز.

## كيف بيشتغل

مسجّل Playwright الجاهز مقيّد بـ 25 إطار/ثانية و1 ميجابت/ثانية webm (أرقام ثابتة في كوده)، فما انستعمل. عوضاً عنه: Chromium بيرسل الإطارات JPEG عبر CDP screencast، كل إطار ينكتب لـ ffmpeg مرة وحدة بوقت وصوله، و ffmpeg بيحوّلها لفيديو بمعدل ثابت (`fps` filter) ويرمّزها H.264. النتيجة: مدة الفيديو مطابقة لمدة التسجيل، وأنت متحكم بالإطارات والجودة والصيغة.

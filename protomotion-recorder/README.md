# Figma Prototype Recorder

سكربت بيفتح رابط بروتوتايب Figma في متصفح، بيشغّله، وبيسجّله فيديو **mp4 بنفس مقاس الفريم تاعك بالظبط** — بدون تكبير ولا تصغير ولا زوم.

**التصوير والترميز مرحلتين منفصلتين**: أثناء التسجيل الإطارات بس بتنحفظ على القرص (شغل خفيف)، والفيديو بينرمّز بعد ما توقف. هيك الترميز البطيء ما بيقدر لا يبطّئ التصوير ولا يطلّع الفيديو slow motion.

## التنصيب (مرة وحدة)

محتاج [Node.js](https://nodejs.org) مثبّت على الجهاز.

افتح PowerShell جوّا مجلد `protomotion-recorder` وشغّل:

```
npm install
npx playwright install chromium
```

(`npm install` بينزّل كمان نسخة ffmpeg جاهزة، فما إلك حاجة تنصّب إشي غيرها.)

## الاستخدام

حدّد مقاس الفريم اللي عندك في Figma:

```
node record.js -u "رابط_البروتوتايب" -w 1920 -h 1226
```

الفيديو بينحفظ `prototype.mp4` — H.264، 60 إطار/ثانية، بمقاس 1920×1226 بالظبط.

**التسجيل بيوقف لما تضغط Enter.** ما في توقف تلقائي ولا screenshots أثناء التصوير. في بس حد أقصى للأمان (`-m`، افتراضياً 10 دقايق).

## الخيارات

| الخيار | الوصف | الافتراضي |
|---|---|---|
| `-u, --url` | رابط بروتوتايب Figma (مطلوب) | — |
| `-o, --output` | مسار ملف الإخراج — `.mp4` أو `.webm` | `prototype.mp4` |
| `-w, --width` | عرض الفريم في Figma | `1920` |
| `-h, --height` | ارتفاع الفريم في Figma | `1080` |
| `--fps` | إطارات بالثانية | `60` |
| `-q, --quality` | جودة الترميز (CRF) — أقل = أنقى وأكبر حجماً | `18` |
| `--jpeg` | جودة الإطارات المسحوبة من المتصفح (1–100) — قلّلها لو المتصفح ما بيلحق | `92` |
| `--preset` | سرعة/جودة ترميز x264: `ultrafast` … `slow` — الترميز بعد التسجيل فالأبطأ آمن | `veryfast` |
| `--keep-frames` | يخلّي مجلد الإطارات `.jpg` بعد الترميز بدل ما يحذفه | مطفي |
| `-m, --maxdur` | حد أقصى لمدة التسجيل بالثواني (أمان) | `600` |
| `-p, --pause` | ثواني بين كل ضغطة تلقائية | `2` |
| `--manual` | إنت بتضغط بنفسك، السكربت بيسجّل بس | مطفي |
| `--headless` | تشغيل بدون متصفح ظاهر | مطفي |
| `--uncap` | يشيل قيد الـ vsync عن Chromium — ممكن يرفع الإطارات وممكن يعمل تهزيز، جرّب الاثنين | مطفي |
| `--debug` | يطبع تغيّرات حجم الـ canvas | مطفي |

## أمثلة

```
node record.js -u "https://figma.com/proto/..." -w 1920 -h 1226
node record.js -u "https://figma.com/proto/..." -w 1920 -h 1226 --manual
node record.js -u "https://figma.com/proto/..." -w 1920 -h 1226 --fps 30
node record.js -u "https://figma.com/proto/..." -w 1920 -h 1226 -o clip.webm
```

## قراءة الأرقام أثناء التسجيل

كل 5 ثواني بيطبع سطر حالة:

```
[ 15s] 55.6 fps painted  frames 718  disk 19 MB
```

- **fps painted** = الإطارات اللي المتصفح فعلياً رسمها بهالفترة. لو قريبة من `--fps` فالحركة ناعمة.
- **disk** = حجم الإطارات المحفوظة (تقريباً 1–1.5 MB لكل ثانية على 1920؛ بتنحذف بعد الترميز).

وبعد التوقف بيبدأ الترميز مع عدّاد تقدّم، وبالنهاية:

```
Length:    20.4s of recording -> 20.4s of video, real speed
Frames:    60 fps in the file; browser painted 51.0 fps on average
```

## المشاكل اللي انحلّت (عشان ما ترجع)

1. **الفيديو بيطلع slow motion رغم إن التصوير تمام.** السبب: النسخة السابقة كانت ترمّز أثناء التصوير، و ffmpeg كان يختم كل إطار بوقت **قراءته من الأنبوب** مش وقت التقاطه. لما الترميز أبطأ من التصوير (جهاز أضعف، مقاس كبير)، الإطارات تتأخر بالأنبوب فالأزمنة تتمطط والفيديو يطلع أبطأ من الحقيقة. الحل: الإطارات بتنحفظ على القرص مع **وقت التقاطها**، والترميز بعد التوقف بيبني الفيديو من هاي الأوقات بالظبط (concat demuxer). السرعة اتحققت بقياس ساعة مرسومة داخل الصفحة: 10 ثواني فيديو = 10.00 ثواني حقيقية.
2. **تقطّع الحركة بعد أول ~15 ثانية.** السبب: الترميز كان يسرق CPU من المتصفح أثناء التصوير ويتراكم عليه الشغل. بفصل المرحلتين اختفى التنافس — القياس: التصوير قفز من ~37 لـ ~51–60 إطار مرسوم بالثانية على نفس الجهاز.
3. **إعدادات `--disable-frame-rate-limit` / `--disable-gpu-vsync`** كانت مفتوحة دايماً وبتخرب انتظام الإطارات. صارت مطفية، ومين بدّه يجربها في `--uncap`.

**لو التصوير نفسه بطيء عندك** (fps painted منخفض)، بالترتيب:

```
node record.js -u "..." -w 1920 -h 1226 --jpeg 75      # سحب الإطارات أخف
node record.js -u "..." -w 1920 -h 1226 --fps 30       # 30 إطار حقيقي أنعم من 60 نصهم مكرر
node record.js -u "..." -w 1920 -h 1226 --uncap        # جرّب بلا سقف vsync
```

وسكّر البرامج التقيلة (Photoshop / AE) أثناء التصوير.

## كيف بيشتغل

مسجّل Playwright الجاهز مقيّد بـ 25 إطار/ثانية و1 ميجابت/ثانية webm (أرقام ثابتة في كوده)، فما انستعمل. عوضاً عنه مرحلتين:

1. **التقاط**: Chromium بيرسل الإطارات JPEG عبر CDP screencast، وكل إطار بينحفظ على القرص فوراً مع وقت التقاطه. ما في أي ترميز بهاي المرحلة.
2. **ترميز**: بعد التوقف، بينبني ملف `ffconcat` فيه مدة عرض كل إطار من فروقات أوقات الالتقاط، و ffmpeg بيحوّله لفيديو بمعدل ثابت (`fps` filter) H.264 أو VP9.

النتيجة: مدة الفيديو وسرعته مطابقين للتسجيل مهما كان الترميز بطيء، والإطارات بتنحذف تلقائياً بعد النجاح (بتضل بس لو فشل الترميز أو مع `--keep-frames`).

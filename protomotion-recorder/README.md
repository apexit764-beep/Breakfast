# Figma Prototype Recorder

سكربت بيفتح رابط بروتوتايب Figma، بيشغّله، وبيطلعلك فيديو **mp4 بنفس مقاس الفريم تاعك بالظبط** وبـ **60 إطار حقيقي بالثانية** — نعومة مثالية مهما كان جهازك.

## التنصيب (مرة وحدة)

محتاج [Node.js](https://nodejs.org) مثبّت على الجهاز.

افتح PowerShell جوّا مجلد `protomotion-recorder` وشغّل:

```
npm install
npx playwright install chromium
```

(`npm install` بينزّل كمان نسخة ffmpeg جاهزة، فما إلك حاجة تنصّب إشي غيرها.)

## الاستخدام

حدّد مقاس الفريم اللي عندك في Figma:

```
node record.js -u "رابط_البروتوتايب" -w 1920 -h 1226
```

الفيديو بينحفظ `prototype.mp4` — H.264، 60fps، بمقاس 1920×1226 بالظبط.

اضغط **Enter** بأي لحظة عشان توقف وتحفظ.

## وضعين للتصوير

### Smooth (الافتراضي) — 60fps مضمونة على أي جهاز

السكربت **بيوقف ساعة الصفحة** (rAF, performance.now, timers) وبيحركها بنفسه 16.67ms لكل إطار، وبيلقط كل إطار لحاله. النتيجة: **كل إطار بالفيديو رندر حقيقي مختلف ومتباعد بالظبط** — النعومة ما عادت تعتمد على سرعة جهازك إطلاقاً.

الالتقاط بياخد وقت أطول من مدة الفيديو (مثلاً 10 ثواني فيديو ≈ 30–60 ثانية التقاط) — **الفيديو النهائي بيطلع بالسرعة الحقيقية تماماً**، بس الالتقاط بيشتغل على مهله. الضغطات التلقائية بتصير بتوقيت الفيديو، فالنتيجة مطابقة لتشغيل حقيقي.

هالوضع تلقائي (auto-click). القياس المرجعي: 10 ثواني = 600 إطار، كلهم فريدين 100%، والسرعة 1:1 بالمللي ثانية.

### Realtime (`--realtime` أو تلقائياً مع `--manual`)

البروتوتايب بيشتغل حي وبنلقط الإطارات اللي المتصفح بيلحق يرسمها. ضروري للوضع اليدوي (إنت بتضغط)، بس النعومة محكومة بسرعة الجهاز لحظة التسجيل.

> **ملاحظة صريحة**: ما في أي طريقة "تسجيل مباشر" بتتغلب على هالحد — كل التسجيل الحي (OBS، مسجّل المتصفح، أي أداة) بيسجّل بس الإطارات اللي انرسمت فعلاً. الوضع الـ Smooth هو الوحيد اللي بيضمن 60 إطار حقيقي لأنه بيرسمهم واحد واحد.

## الخيارات

| الخيار | الوصف | الافتراضي |
|---|---|---|
| `-u, --url` | رابط بروتوتايب Figma (مطلوب) | — |
| `-o, --output` | مسار ملف الإخراج — `.mp4` أو `.webm` | `prototype.mp4` |
| `-w, --width` | عرض الفريم في Figma | `1920` |
| `-h, --height` | ارتفاع الفريم في Figma | `1080` |
| `--fps` | إطارات بالثانية | `60` |
| `-q, --quality` | جودة الترميز (CRF) — أقل = أنقى وأكبر حجماً | `18` |
| `--jpeg` | جودة الإطارات الملتقطة (1–100) | `92` |
| `--preset` | سرعة/جودة ترميز x264: `ultrafast` … `slow` — الترميز بعد التسجيل فالأبطأ آمن | `veryfast` |
| `-m, --maxdur` | حد أقصى بالثواني — بوضع Smooth هي مدة **الفيديو** مش الالتقاط | `600` |
| `-p, --pause` | ثواني بين الضغطات التلقائية (بتوقيت الفيديو) | `2` |
| `--manual` | إنت بتضغط بنفسك (بيفعّل realtime تلقائياً) | مطفي |
| `--realtime` | تصوير حي بدل الوضع الحتمي | مطفي |
| `--headless` | تشغيل بدون متصفح ظاهر | مطفي |
| `--uncap` | (realtime بس) رسم بلا سقف vsync | مطفي |
| `--keep-frames` | يخلّي مجلد الإطارات بعد الترميز | مطفي |
| `--encode-from <مجلد>` | يرمّز مجلد إطارات محفوظ (بعد ترميز فاشل) بدون إعادة تصوير | — |
| `--debug` | يطبع تغيّرات حجم الـ canvas | مطفي |

## أمثلة

```
node record.js -u "https://figma.com/proto/..." -w 1920 -h 1226
node record.js -u "https://figma.com/proto/..." -w 1920 -h 1226 --fps 30
node record.js -u "https://figma.com/proto/..." -w 1920 -h 1226 -q 14 --preset slow
node record.js -u "https://figma.com/proto/..." -w 1920 -h 1226 --manual
```

## قراءة الأرقام

أثناء الالتقاط بوضع Smooth:

```
[  4.6s video] 278 frames  disk 7 MB  capturing at 0.33x real time
```

يعني: وصلنا لثانية 4.6 من الفيديو، والالتقاط ماشي بثلث السرعة الحقيقية (طبيعي). وبالنهاية:

```
Length:    10.0s of video at a true 60 fps - every frame is a distinct render
Capture:   took 31s of real time (0.32x)
```

بوضع Realtime بتشوف `fps painted` — الإطارات اللي المتصفح لحق يرسمها فعلياً.

## المشاكل اللي انحلّت (تاريخ التطوير)

1. **فيديو slow motion رغم إن التصوير تمام**: الترميز كان أثناء التصوير و ffmpeg يختم الإطارات بوقت قراءتها من الأنبوب مش وقت التقاطها؛ لما الترميز يبطأ تتمطط الأزمنة. الحل: الإطارات بتنحفظ عالقرص مع وقتها الحقيقي والترميز بعد التوقف.
2. **تقطّع بعد ~15 ثانية**: الترميز كان يسرق CPU من المتصفح ويتراكم. انحل بفصل المرحلتين.
3. **إحساس عدم نعومة رغم ملف 60fps**: التسجيل الحي بيلقط 40–50 إطار غير منتظمين وبينفردو على شبكة 60 → judder. انحل جذرياً بوضع Smooth (كل إطار مرسوم فعلياً).
4. **مقيّدات Playwright**: مسجّله الجاهز مقفول 25fps / 1Mbps webm — انستبدل كلياً.

## لو فشل الترميز بعد ما خلص الالتقاط

الإطارات ما بتضيع — السكربت بيطبعلك مسار المجلد المحفوظ. رمّزها بدون إعادة تصوير:

```
node record.js --encode-from "مسار_مجلد_الإطارات" -o prototype.mp4
```

(بياخد مقاس الإطارات نفسها تلقائياً ويضبطه لأرقام زوجية.)

## ملاحظات

- الإطارات بتنحفظ مؤقتاً بمجلد جنب ملف الإخراج (~1.5 MB لكل ثانية) وبتنحذف بعد الترميز؛ بتضل بس لو فشل أو مع `--keep-frames`.
- وضع Smooth بيبدّل ساعة الصفحة، فلو البروتوتايب فيه **فيديو مضمّن** جوّاه ما رح يتحرك بتوقيت مضبوط — هاي الحالة الوحيدة اللي بتحتاج `--realtime`.
- الأبعاد الفردية بتنضبط لأقرب زوجي (ترميز الفيديو بيفضّل الزوجي).
